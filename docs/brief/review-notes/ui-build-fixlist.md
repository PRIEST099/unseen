# UI build (Kiro IDE): product-lead fix list

Issues found while verifying each task during the nonstop IDE run.

**Decision (user, 2026-11-25):** these are **not** sent back to Kiro. Once Kiro has finished every `spirit-sight-ui` task (through 3.5), Claude Code applies all items below in **one** fix pass, on its own commits labelled `fix-pass (Claude Code)`, logged in `KIRO_SESSION_LOG.md` so the split between Kiro-built and Claude-fixed code stays transparent. Until then, items are only collected here; nothing is edited while the IDE run is going.

| # | Task | Issue | Fix |
|---|---|---|---|
| 1 | 1.1 | `onProgress` reports each stage when it **finishes** ("loading" fires after the page has loaded, "tree" after the AX tree is collected). Decision N and the spec say stages are emitted when each one **starts**. The séance would show nothing during the slowest step, then jump ahead. | Emit `loading` before `loadPage`, `tree` before `collectAxTree`, `walking` before the Tab walk and `classifying` before `classify`. Update `progress.int.spec.ts` to assert the start order. |
| 2 | 1.2 | `apps/web/samples/.gitignore` excludes `*.png` and `*.jpg`, but the spec and decisions say the sample screenshots and thumbnails are **committed**. Without them, the guaranteed sample demo path breaks on a fresh clone and on the deployed box. | Delete `samples/.gitignore` and commit the PNGs and JPGs. |
| 3 | 1.2 | The sample display URL is an invented real-looking domain, `https://the-unseen.app/cursed-shop/...`, which we do not own. | Use a relative `/cursed-shop/<page>.html` display URL, or `PUBLIC_BASE_URL` from env when set. Never hard-code a domain. |
| 4 | 1.5 (design) | The landing page is clean but plain: ink background, title, input, sample cards. It does not yet deliver the brief's "candle-lit dark page" and Victorian-séance mood (Costume Contest; Design is 20%). | Add atmosphere on the landing hero: a subtle candle glow (radial `--color-candle` gradient), a vignette, a faint noise texture and a larger display title. Keep it on-token and AA, and disable all of it under reduced motion. |
| 5 | 1.5 (design) | "Haunting Score: 98" on the sample cards does not say what the number means. Higher = more haunted, which first-time visitors will not guess. | Show "98 / 100 · heavily haunted", or similar severity wording, plus an accessible explanation ("Haunting Score out of 100; higher means more accessibility barriers"). |
| 6 | 1.6 (**demo-critical**) | The fog wave is a 128 px band that sweeps down and **clears completely behind itself** (`fog-canvas.ts` `paint()` calls `clear()` each frame; nothing persists after `finish()`). After "Open Spirit Sight" the page therefore looks almost unchanged, apart from the overlays. The brief's signature moment ("page elements dissolve into fog in a wave from top to bottom, then the whispers begin"; demo beat 0:15–0:45, "half the page fogs over") does not happen. | Make the wave **leave fog behind**. Above the band, keep a persistent haunted state: the screenshot dimmed and desaturated (for example `filter: grayscale(.6) brightness(.7)`, the same look as the reduced-motion variant), plus a low-alpha persistent mist (about 0.3) over the whole screenshot. Draw denser fog over The Fog nodes, scaled by contrast deficit. Make the moving band taller and denser (about 240 px) so it reads on video, and let the overlays glow on top of the fog. Closing Spirit Sight clears it instantly. Add a test that the canvas still has painted pixels after the wave completes. |
| 7 | 1.6 | The heading uses the invented domain ("Spirit Sight: the-unseen.app"); see item 3. | Fixed by item 3: show the real audited host, or "Cursed Shop (sample)" for samples. |
| 8 | 1.4/1.7 (tests) | `src/server/routes/audit.int.test.ts` launches real Chromium (an 8 s end-to-end audit). In the full parallel `vitest --run` under load it failed at suite level, but alone it passes 2/2. | Move browser-backed tests out of the default parallel unit run: a separate `test:int` script, or the vitest `pool: 'forks'` with `singleFork` for `*.int.test.ts`, plus a generous `testTimeout`. Keep `npm test` fast and deterministic. |
