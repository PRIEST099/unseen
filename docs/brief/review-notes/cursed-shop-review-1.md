# Cursed Shop review 1 (independent, Claude Code reviewers)

> Evidence paths below of the form `<scratch>/...` were on the local build machine and are not committed. The reusable probe scripts are in [`probes/`](probes/README.md).

Three read-only reviewers (visual, hauntings, keyboard) tested Kiro's vibe-coded shop in real Chromium on 2026-11-20.

**Verdict:** No, the shop is not demo-ready. Measured against hauntings.md, most planted hauntings either don't fire or fire at different counts than expected-hauntings.json claims: Nameless Spirit and Hollow Portrait are 0 on every page, index Lost Soul is 0, Whispering Field is 0, Silent Tongue and Shattered Order are missing from the golden file, and the checkout modal is not a genuine 2.1.2 trap. Visually, the candle art looks like clip-art, the layout overflows horizontally at 390px on every page, the checkout has visibly unstyled pieces and a promo bar covering the CTA, and the hero is flat. A judge would notice all of this within seconds. All three reviewers' evidence agrees, and I re-checked the disputed points myself in Chromium: the AX tree while the modal is open, placeholder naming, svg role="none", and the contrast ratios.

## Reviewer: visual

Visual verdict: NOT yet believable as a premium candle/apothecary store. The palette (warm browns and cream), the header and footer system, and the desktop grid are consistent and pleasant. Three things undermine it badly enough that a judge would notice in the first 5 seconds:
(1) The product imagery is crude clip-art. Each candle is a pastel rectangle drawn like a test tube. The flame and glow sit outside the SVG viewBox, so they are clipped. Label words overflow their label boxes. On the index the image is cropped by object-fit:cover so no flame shows at all. "Midnight Wood" is drawn bright pink.
(2) At 390px the layout breaks: documentElement.scrollWidth is 485 on all 3 pages. The header never collapses, so the logo wraps onto 2 lines, "Contact" is cut off and both header icons are off-screen.
(3) Checkout has several obviously unstyled or broken pieces: browser-default "Subscribe"/"No thanks" buttons in Arial, Arial leaking into the main CTA, a checkbox floating centered above its label, a fixed promo bar covering the checkout CTA at 1280x900 (elementFromPoint returned .promo-banner), and a large empty white area under the Order Summary.
Secondary issues: a flat muddy hero with a stray arc line and a section title glued to it; malformed footer social icons (Instagram looks like a die); a cart icon that is a "+"; no UI path to checkout.html; the product page always shows Midnight Wood.
Evidence (screenshots and scripts) is in <scratch>/shop-review/visual/ (index/product/checkout-1280-full.png, *-390-*.png, z-*.png, out.json, shoot.mjs, shoot2.mjs).
Out of visual scope but noticed, for the a11y reviewers:
- index.html product images have alt="" (lines 606-697), and product.html .product-thumb/.product-image-related also have alt="". Per hauntings.md, alt="" counts as decorative and must NOT be flagged, so the expected Hollow Portrait counts are likely unreachable. checkout .cart-item-image has real alt text ("Midnight Wood candle"), but the golden file expects 2 Hollow Portraits there.
- checkout .promo-link has aria-hidden="true" and tabindex="-1", but the golden file expects it as an Invisible Wanderer, which requires it to be in the Tab walk.
- .hidden-from-ax is positioned at -9999px, so it is not visually present.

## Reviewer: hauntings

The golden file and the shop don't match. Most planted hauntings either don't fire, fire a different number of times than the golden file says, or are filed under the wrong type. I checked all 3 pages in Playwright 1.65.1 / Chromium using axe-core 4.14.1 (wcag2a/aa, wcag21a/aa, wcag22aa), CDP Accessibility.getFullAXTree, DOMDebugger.getEventListeners, and a real Tab walk that compares focus styles before and after each Tab. Measured against hauntings.md, here are the actual counts per page, with the golden figure in brackets.

index.html:
- Nameless Spirit 0 [8]
- Hollow Portrait 0 [6]
- Fog 1 [8]
- Lost Soul 0 [4]
- Invisible Wanderer: 21 elements have no visible focus change. A literal reading of the rule finds only 2, because of a browser default for links (see findings). [4]
- Whispering Field 0 [3, and those 3 are social links]
- Veiled 0, or 3 aria-hidden feature icons under a strict reading [0]
- Silent Tongue 0, Shattered Order 0, Cursed Loop 0 (correct)

product.html:
- Nameless Spirit 0 [2]
- Hollow Portrait 0 [4]
- Fog 14 axe nodes [4]
- Lost Soul 10 [4]
- Invisible Wanderer 7 real, 0 by the literal rule [3]
- Shattered Order 1: the headings jump h2→h4, not h1→h4. The golden file lists this under controls (must not be flagged) instead of hauntings.

checkout.html:
- Nameless Spirit 0 [2]
- Hollow Portrait 0 [2]
- Fog 4 axe nodes [2]

- Invisible Wanderer 9 real, 2 by the literal rule [4]

- Cursed Loop 1, which the rule detects. It isn't a true trap: pressing Enter on the × button closes the modal.
- Veiled 2 [1]

Root causes:
1. Every icon-only button and link has an aria-label.
2. Every "no-alt" image has alt="".
3. The placeholder-only fields have real <label for> elements. Chromium also uses the placeholder as the accessible name, so a placeholder-only field is never nameless under the current rule.
4. The clickable product cards on index.html contain a native button, so the Lost Soul skip rule excludes them.
5. Chromium's built-in focus style changes outline-offset from 0px to 1px on focused links, so `outline: none` links count as "visible" under the literal rule.
6. Several required plantings are missing: the Quick-view div, the aria-hidden promo banner on index.html, the Free-shipping badge, and a modal with no keyboard-reachable close.

The cookie-banner control isn't a dialog, doesn't cycle focus, and doesn't close on Escape. Pressing Escape left the banner unchanged.

Many golden selectors match a different number of elements than the count beside them, or match nothing at all: `.product-grid .product-note:nth-child(4)` matches 0, and `.promo-link` is not in the Tab order.

## Reviewer: keyboard

I ran keyboard and assistive-tech QA with real key presses in Playwright 1.65.1 (channel 'chromium', viewport 1280x900, file:// URLs) on index, product and checkout. I did not modify anything in the repo. Scripts, logs and screenshots are in <scratch>/shop-review/keyboard/ (kb.mjs/run1.log, kb2.mjs/run2.log, kb3.mjs/run3.log, *.png).

Bottom line: none of the three pages logs a JS error. The Lost Soul elements really are unreachable by Tab and do respond to mouse clicks. Three problems undercut the demo, though.
(1) The checkout newsletter modal is NOT a genuine WCAG 2.1.2 keyboard trap. Focus does cycle only inside it and Escape does nothing, but one Tab to "No thanks" plus Enter closes it, and so does the × button or entering an email.
(2) The index cookie banner, which is supposed to be the control case, has no Escape handling at all (no keydown listeners anywhere), does not keep focus inside it, and its buttons stay in the Tab order off-screen after it is dismissed.
(3) Several golden counts would not match what the detector finds under the hauntings.md rules:
- index Lost Soul would be 0, not 4, because each clickable card contains a native button, which the rule's skip clause excludes.
- product Lost Soul would be 10, not 4.
- Most Invisible Wanderer links would NOT be flagged, because Chrome's default focus style shifts outline-offset from 0px to 1px even under outline:none, and hauntings.md counts any outline-offset change as a visible indicator.
- index .add-to-cart-btn and checkout .promo-link are listed as Invisible Wanderers but cannot be one (the first has a visible focus ring, the second is never reachable by Tab).

Smaller issues: the checkout modal opens on a 1-second timer, so whether the detector sees the trap depends on timing. On checkout, the fixed promo banner hides focus on the City and State fields. On product, the header icon buttons get a white focus outline on a white header, so there is no visible focus even though the detector would count it as visible.
